## Requirements

### Fab-Kit Version Pins: Consistency

#### R1: Pinned kit version matches the target
`fab/.fab-version` MUST read exactly `2.16.4` (the repo's pinned kit version, advanced from `2.16.0` by the upgrade tool).

- **GIVEN** `fab upgrade-repo` ran with target kit 2.16.4
- **WHEN** `fab/.fab-version` is read
- **THEN** its sole content is `2.16.4`

#### R2: Migration-state marker matches the target
`fab/.kit-migration-version` MUST read exactly `2.16.4` (advanced from `2.15.8`; no migration steps required manual action).

- **GIVEN** the upgrade tool advanced the migration marker to the target version
- **WHEN** `fab/.kit-migration-version` is read
- **THEN** its sole content is `2.16.4`

#### R3: Config reference-fence header matches the target
`fab/project/config.yaml`'s generated reference-fence header MUST read `# >>> fab reference (kit 2.16.4) >>>`, and no user-override fields above the fence may be altered.

- **GIVEN** the fence body is regenerated by the upgrade tool
- **WHEN** the fence header line is read and the pre-fence fields are diffed
- **THEN** the header names `kit 2.16.4` AND the only diff in the file is the header version string (no field additions/removals/reorderings above the fence)

### Diff Scope: Exactly the Three Tracked Files

#### R4: Committable diff is exactly the three version files
The tracked (committable) diff MUST be exactly `fab/.fab-version`, `fab/.kit-migration-version`, and `fab/project/config.yaml` (+3/−3 lines total). `.claude/` re-sync side effects are gitignored and MUST NOT appear as tracked changes.

- **GIVEN** the upgrade tool applied version pins and re-synced `.claude/` skills
- **WHEN** `git diff --stat` (tracked, excluding the change folder itself) is inspected
- **THEN** exactly three files show as modified, +3/−3 lines, and no `.claude/` path appears as tracked

### Tree Health: Regression Guard

#### R5: Go module builds and tests pass
The Go module (rooted at `src/`) MUST build and pass its test suite unchanged — a cheap regression guard confirming the version bump left the tree healthy (no source code is touched by this change).

- **GIVEN** no source code under `src/` is modified by this change
- **WHEN** `go build ./...` and `go test ./...` run from `src/`
- **THEN** both complete with exit code 0

### Non-Goals

- Re-running `fab upgrade-repo` — the diff pre-exists; a re-run would be a no-op at best.
- Hand-editing any of the three version files — the upgrade tool is the sole sanctioned mechanism.
- Committing or shipping — that is the pipeline's ship stage, downstream of apply.
- Any change to the `idea` CLI surface, help output, README, or docs/site — out of scope and untouched.
