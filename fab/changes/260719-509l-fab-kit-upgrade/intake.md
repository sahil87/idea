## Why

The repo pins its fab-kit version in `fab/.fab-version`; kit 2.16.4 is available (this worktree was at 2.16.0). Running `fab upgrade-repo` keeps the deployed skills, config reference fence, and migration state in sync with the installed kit. If not committed, the worktree drifts from the recorded kit version: future `fab sync` runs would re-report stale versions, and other worktrees/clones would resolve a different kit than the one whose skills are actually deployed. The upgrade tool is the only sanctioned mechanism for this (no hand-editing of version files), so the approach is fixed — run the tool, commit its output.
